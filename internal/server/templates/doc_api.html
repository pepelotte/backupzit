REST API

Integrate BackupZit with RMM platforms, monitoring (PRTG, Zabbix, Nagios, Uptime Kuma …) and your own scripts.

Tokens

Create a token under My account → API tokens. Give it the lowest role that is enough — Viewer for monitoring, Restore operator to also start backups and restore tests. The token is shown once; send it in every request:

Authorization: Bearer bzt_...

Tokens can expire, can be revoked by their owner or an administrator (Users), and stop working when the owner is disabled. Actions done with a token appear in the audit log with the token's name.

Endpoints

All responses are JSON. Base URL: https://<console>:8443.

Method and pathRoleReturns
GET /api/v1/statusViewerOverall health: agents online, failures and warnings in 24 h, active runs, unreviewed suspicious backups, "ok": true|false
GET /api/v1/agentsViewerAgents with OS, version, online state and last contact
GET /api/v1/jobs, GET /api/v1/jobs/{id}ViewerJobs with schedule, next run and last result; also their settings: schedule_spec, retention, options, image_disk, image_partitions
POST /api/v1/jobsBackup operatorCreates a job: files, disk image (one disk, all disks with -1, or some partitions), Linux system or copy, e.g. {"name": "PC-07", "kind": "image", "agent_id": 12, "target_id": 3, "image_disk": 0, "image_partitions": [3], "schedule": {"kind": "daily", "days": [1, 2, 3, 4, 5], "times": ["22:00"]}, "retention": {"keep_daily": 14}}; checked like the job form. Commands before and after a backup need the Administrator role
PATCH /api/v1/jobs/{id}Backup operatorChanges name, paths, excludes, schedule, retention or options; fields not given stay. With four-eyes approval a shorter retention is changed in the console (409)
DELETE /api/v1/jobs/{id}Backup operatorDeletes the job; its backups remain on the storage. With four-eyes approval only in the console (409)
POST /api/v1/jobs/{id}/runRestore operatorStarts the job now: {"run_id": 123} (202), or 409 if a run is already active
POST /api/v1/jobs/{id}/testRestore operatorStarts a restore test of the job's newest backup
GET /api/v1/runs?job=&agent=&status=&limit=ViewerRecent runs, newest first (default 100, max 1000)
GET /api/v1/runs/{id}ViewerOne run with message, errors and statistics
GET /api/v1/report?period=&from=&to=&agent=&job=ViewerThe report for a period: totals, success rate and per-job details
GET /api/v1/targetsViewerStorage targets (without credentials)
POST /api/v1/targetsAdministratorCreates a storage target with the fields of the Storage form, e.g. {"name": "Customer A", "kind": "s3", "s3_endpoint": "…", "s3_bucket": "…", "s3_access_key": "…", "s3_secret_key": "…", "s3_lock_days": 30}; encrypted unless "encrypted": false. Tests the connection and returns the recovery key once — keep it safe
POST /api/v1/targets/{id}/testAdministratorTests the connection to the storage: {"ok": true, "message": "…"}
POST /api/v1/agents/enroll-codeBackup operatorA code to enroll one agent, valid for 7 days: {"code": "BZ1-…", "expires": "…"}
GET /api/v1/agents/{id}ViewerOne agent, with the disks and partitions it reported (their numbers select them in image jobs)
POST /api/v1/agents/{id}/logBackup operatorAsks the agent for its log: {"run_id": 124}; read it with the next endpoint once the agent has sent it (agents 0.38.0 or newer)
GET /api/v1/runs/{id}/logBackup operatorThe log an agent sent: {"log": "..."}, or 404 until it arrives
POST /api/v1/runs/{id}/cancelRestore operatorCancels a queued run or stops a running one: {"state": "cancelled"} or "stopping"; 409 if it has finished
POST /api/v1/jobs/{id}/enable, /disableBackup operatorTurns the job's schedule on or off; with four-eyes approval on, disabling works only in the console (409)
GET /api/v1/storageViewerSpace used per storage target, the capacity and free space when known, the growth per day and the days until full
GET /api/v1/metricsViewerMetrics in the Prometheus text format (see below)
POST /api/v1/runs/{id}/restoreRestore operatorRestores files of a backup run with an agent: body {"target": "D:/Restore"} or {"original": true}, optionally "paths", "agent_id" and "verify": true; returns {"run_id": 125}
GET /api/v1/runs/{id}/files?path=Restore operatorLists a folder of a file or Linux system backup on network storage (path= from the previous listing): {"entries": [{"name": "…", "path": "…", "dir": false, "size": 16, "modified": "…"}]}
POST /api/v1/runs/{id}/files/downloadRestore operatorDownloads files of the backup: body {"paths": ["…"]}; one file as is, several or folders as a ZIP archive
GET /api/v1/openapi.jsonno tokenThe OpenAPI 3 specification of this API, for tools and client generators (also in the repository: internal/server/openapi.json)

Periods: today, yesterday, last7, last30, last90, thisweek, lastweek, thismonth, lastmonth, or custom with from=2026-09-01&to=2026-09-30.

Errors return {"error": "..."} with 400 (bad request), 401 (missing, invalid or expired token), 403 (role too low), 404 or 409.

Examples

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

Use -k / -SkipCertificateCheck only with the console's self-signed certificate on a trusted network, or install the console certificate on the monitoring host.

Monitoring check

Poll /api/v1/status every few minutes and alert when ok is false. For per-job checks use /api/v1/jobs and alert when last_status is failed or last_finished is older than expected.

Jobs with an RPO also return rpo_hours, rpo_met and last_good_backup; agents return max_runs (jobs at once). The metric backupzit_job_rpo_met is 1 for a job within its RPO and 0 for one that missed it.

Prometheus and Grafana

/api/v1/metrics returns the state in the Prometheus text format: agents online, active runs, failures and warnings of the last 24 hours, suspicious backups, and per agent, job and storage target backupzit_agent_online, backupzit_job_last_status (0 success, 1 warning, 2 failed), backupzit_job_last_success_timestamp_seconds, backupzit_storage_used_bytes and backupzit_storage_free_bytes. A scrape job with a Viewer token:

- job_name: backupzit
  scheme: https
  metrics_path: /api/v1/metrics
  authorization:
    credentials: bzt_...
  static_configs:
    - targets: ['backup.example.local:8443']

Alert, for example, when time() - backupzit_job_last_success_timestamp_seconds > 2*86400 (no good backup for two days).
