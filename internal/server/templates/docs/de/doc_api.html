REST API

Binden Sie BackupZit an RMM-Plattformen, Überwachung (PRTG, Zabbix, Nagios, Uptime Kuma …) und eigene Skripte an.

Token

Erstellen Sie ein Token unter Mein Konto → API-Token. Geben Sie ihm die niedrigste Rolle, die genügt — Betrachter für die Überwachung, Wiederherstellungsoperator, um auch Sicherungen und Wiederherstellungstests zu starten. Das Token wird nur einmal angezeigt; senden Sie es mit jeder Anfrage:

Authorization: Bearer bzt_...

Token können ablaufen, von ihrem Besitzer oder einem Administrator widerrufen werden (Benutzer) und funktionieren nicht mehr, wenn der Besitzer deaktiviert wird. Mit einem Token ausgeführte Aktionen erscheinen im Prüfprotokoll mit dem Namen des Tokens.

Endpunkte

Alle Antworten sind JSON. Basis-URL: https://<konsole>:8443.

Methode und PfadRolleLiefert
GET /api/v1/statusBetrachterGesamtzustand: Agenten online, Fehler und Warnungen in 24 h, aktive Läufe, ungeprüfte verdächtige Sicherungen, "ok": true|false
GET /api/v1/agentsBetrachterAgenten mit Betriebssystem, Version, Online-Status und letztem Kontakt
GET /api/v1/jobs, GET /api/v1/jobs/{id}BetrachterAufträge mit Zeitplan, nächstem Lauf und letztem Ergebnis; dazu ihre Einstellungen: schedule_spec, retention, options, image_disk, image_partitions
POST /api/v1/jobsSicherungsoperatorLegt einen Auftrag an: Dateien, Abbild (eine Festplatte, alle mit -1 oder einzelne Partitionen), Linux-System oder Kopie, z. B. {"name": "PC-07", "kind": "image", "agent_id": 12, "target_id": 3, "image_disk": 0, "image_partitions": [3], "schedule": {"kind": "daily", "days": [1, 2, 3, 4, 5], "times": ["22:00"]}, "retention": {"keep_daily": 14}}; geprüft wie im Auftragsformular. Befehle vor und nach einer Sicherung erfordern die Rolle Administrator. Zeitpläne lassen sich außerdem auf Monate ("months": [1, 4, 7, 10]) und einen Zeitraum ("valid_from", "valid_until") beschränken, monatlich an einem Wochentag ausführen ("week": 1, "weekday": 1 = erster Montag), in einem Zeitfenster mit Minuten ("from_time": "08:30", "to_time": "17:45") oder einige Stunden nach dem vorigen Lauf ({"kind": "since_last", "every_hours": 36})
PATCH /api/v1/jobs/{id}SicherungsoperatorÄndert Name, Pfade, Ausschlüsse, Zeitplan, Aufbewahrung oder Optionen; nicht angegebene Felder bleiben. Mit Vier-Augen-Freigabe wird eine kürzere Aufbewahrung in der Konsole geändert (409)
DELETE /api/v1/jobs/{id}SicherungsoperatorLöscht den Auftrag; seine Sicherungen bleiben im Speicher. Mit Vier-Augen-Freigabe nur in der Konsole (409)
POST /api/v1/jobs/{id}/runWiederherstellungsoperatorStartet den Auftrag sofort: {"run_id": 123} (202), oder 409, wenn bereits ein Lauf aktiv ist
POST /api/v1/jobs/{id}/testWiederherstellungsoperatorStartet einen Wiederherstellungstest der neuesten Sicherung des Auftrags
GET /api/v1/runs?job=&agent=&status=&limit=BetrachterLetzte Läufe, neueste zuerst (Standard 100, maximal 1000)
GET /api/v1/runs/{id}BetrachterEin Lauf mit Meldung, Fehlern und Statistik
GET /api/v1/report?period=&from=&to=&agent=&job=BetrachterDer Bericht für einen Zeitraum: Summen, Erfolgsquote und Details pro Auftrag
GET /api/v1/targetsBetrachterSpeicherziele (ohne Zugangsdaten)
POST /api/v1/targetsAdministratorLegt ein Speicherziel mit den Feldern des Formulars unter Speicher an, z. B. {"name": "Customer A", "kind": "s3", "s3_endpoint": "…", "s3_bucket": "…", "s3_access_key": "…", "s3_secret_key": "…", "s3_lock_days": 30}; verschlüsselt, außer mit "encrypted": false. Testet die Verbindung und gibt den Wiederherstellungsschlüssel einmalig zurück — sicher aufbewahren. Mit "recovery_key_from": 3 verwendet es den Wiederherstellungsschlüssel von Ziel 3 und liefert keinen — ein Schlüssel z. B. für ein NAS und die Cloud-Kopie
POST /api/v1/targets/{id}/testAdministratorTestet die Verbindung zum Speicher: {"ok": true, "message": "…"}
POST /api/v1/agents/enroll-codeSicherungsoperatorEin Code zum Registrieren eines Agenten, 7 Tage gültig: {"code": "BZ1-…", "expires": "…"} Optionaler Body {"ttl_minutes": 120, "single_use": true, "label": "…"}: kürzere Gültigkeit, nur ein Agent, und eine Kennung, die der Agent behält (enroll_label in GET /api/v1/agents)
GET /api/v1/agents/enroll-codes?label_prefix=SicherungsoperatorDie gültigen Enrollment- und Wiederherstellungscodes, ohne den Code selbst: [{"id": 7, "label": "…", "single_use": true, "expires": "…"}]
POST /api/v1/agents/enroll-codes/revokeSicherungsoperatorWiderruft einen Code {"id": 7} oder alle, deren Kennung mit einem Präfix beginnt {"label_prefix": "…"}; bereits registrierte Agenten bleiben
GET /api/v1/agents/{id}BetrachterEin Agent mit den gemeldeten Festplatten und Partitionen (ihre Nummern wählen sie in Abbildsicherungen aus). Partitionen haben used: den belegten Platz bei der neuesten Abbildsicherung
POST /api/v1/agents/{id}/logSicherungsoperatorFordert das Protokoll des Agenten an: {"run_id": 124}; mit dem nächsten Endpunkt lesen, sobald der Agent es gesendet hat (Agenten ab 0.38.0)
GET /api/v1/runs/{id}/logSicherungsoperatorDas gesendete Protokoll: {"log": "..."}, oder 404, bis es eintrifft
POST /api/v1/runs/{id}/cancelWiederherstellungsoperatorBricht einen wartenden Lauf ab oder hält einen laufenden an: {"state": "cancelled"} oder "stopping"; 409, wenn er beendet ist
POST /api/v1/jobs/{id}/enable, /disableSicherungsoperatorSchaltet den Zeitplan des Auftrags ein oder aus; mit Vier-Augen-Freigabe geht das Deaktivieren nur in der Konsole (409)
GET /api/v1/storageBetrachterBelegter Platz je Speicherziel, Kapazität und freier Platz, sofern bekannt, Wachstum pro Tag und Tage bis voll
GET /api/v1/metricsBetrachterMetriken im Prometheus-Textformat (siehe unten)
POST /api/v1/runs/{id}/restoreWiederherstellungsoperatorStellt Dateien einer Sicherung mit einem Agenten wieder her: Body {"target": "D:/Restore"} oder {"original": true}, optional "paths", "agent_id" und "verify": true; liefert {"run_id": 125}. Bei einem Abbild die Pfade so angeben, wie die Dateiliste sie zeigt; "run_ids" nennt einen Lauf pro Volume
POST /api/v1/runs/{id}/restore-diskWiederherstellungsoperatorStellt ein Abbild auf eine ganze Festplatte eines Agenten wieder her, auch eines vom Wiederherstellungsmedium gestarteten: {"disk": 0, "target_disk": 1, "confirm_erase": true}, optional "agent_id", "new_hardware", "keep_offline", "driver_path"; eine Linux-Systemsicherung mit {"device": "/dev/sdb", "confirm_erase": true}. Die Festplatten der Sicherung stehen in image_disks von GET /api/v1/runs/{id}
GET /api/v1/runs/{id}/files?path=WiederherstellungsoperatorListet einen Ordner einer Datei- oder Linux-Systemsicherung auf Netzwerkspeicher auf (path= aus der vorigen Auflistung): {"entries": [{"name": "…", "path": "…", "dir": false, "size": 16, "modified": "…"}]}. Bei einem Abbild zeigt die erste Ebene seine Volumes (C für C:\); Download und Wiederherstellung nehmen dieselben Pfade
POST /api/v1/runs/{id}/files/downloadWiederherstellungsoperatorLädt Dateien der Sicherung herunter: Body {"paths": ["…"]}; eine Datei unverändert, mehrere oder Ordner als ZIP-Archiv
GET /api/v1/openapi.jsonkein TokenDie OpenAPI-3-Spezifikation dieser API für Werkzeuge und Client-Generatoren (auch im Repository: internal/server/openapi.json)

Zeiträume: today, yesterday, last7, last30, last90, thisweek, lastweek, thismonth, lastmonth oder custom mit from=2026-09-01&to=2026-09-30.

Fehler liefern {"error": "..."} mit 400 (ungültige Anfrage), 401 (Token fehlt, ist ungültig oder abgelaufen), 403 (Rolle zu niedrig), 404 oder 409.

Beispiele

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

Verwenden Sie -k / -SkipCertificateCheck nur mit dem selbstsignierten Zertifikat der Konsole in einem vertrauenswürdigen Netz, oder installieren Sie das Konsolenzertifikat auf dem Überwachungshost.

Überwachungsprüfung

Fragen Sie /api/v1/status alle paar Minuten ab und alarmieren Sie, wenn ok false ist. Für Prüfungen pro Auftrag verwenden Sie /api/v1/jobs und alarmieren, wenn last_status failed ist oder last_finished älter als erwartet ist.

Aufträge mit RPO liefern zusätzlich rpo_hours, rpo_met und last_good_backup; Agenten liefern max_runs (gleichzeitige Aufträge). Die Metrik backupzit_job_rpo_met ist 1 für einen Auftrag im RPO und 0 für einen, der es verfehlt hat.

Prometheus und Grafana

/api/v1/metrics liefert den Zustand im Prometheus-Textformat: Agenten online, aktive Läufe, Fehler und Warnungen der letzten 24 Stunden, verdächtige Sicherungen sowie je Agent, Auftrag und Speicherziel backupzit_agent_online, backupzit_job_last_status (0 Erfolg, 1 Warnung, 2 Fehler), backupzit_job_last_success_timestamp_seconds, backupzit_storage_used_bytes und backupzit_storage_free_bytes. Ein Scrape-Job mit einem Betrachter-Token:

- job_name: backupzit
  scheme: https
  metrics_path: /api/v1/metrics
  authorization:
    credentials: bzt_...
  static_configs:
    - targets: ['backup.example.local:8443']

Alarmieren Sie zum Beispiel, wenn time() - backupzit_job_last_success_timestamp_seconds > 2*86400 (zwei Tage keine gute Sicherung).
