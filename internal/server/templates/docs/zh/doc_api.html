REST API

将 BackupZit 与 RMM 平台、监控系统（PRTG、Zabbix、Nagios、Uptime Kuma 等）以及您自己的脚本集成。

令牌

在 我的帐户 → API 令牌 中创建令牌。授予它够用的最低角色 —— 监控用 查看者，若还需启动备份和还原测试则用 还原操作员。令牌只显示一次；在每个请求中发送它：

Authorization: Bearer bzt_...

令牌可以设置过期时间，可由其所有者或管理员撤销（用户），所有者被禁用后令牌也会失效。使用令牌执行的操作会以令牌名称记录在审计日志中。

端点

所有响应均为 JSON。基础 URL：https://<控制台>:8443。

方法和路径角色返回
GET /api/v1/status查看者总体状态：在线代理、24 小时内的失败和警告、正在进行的运行、未检查的可疑备份，"ok": true|false
GET /api/v1/agents查看者代理及其操作系统、版本、在线状态和最后联系时间
GET /api/v1/jobs, GET /api/v1/jobs/{id}查看者作业及其计划、下次运行和上次结果；并含其设置：schedule_spec, retention, options, image_disk, image_partitions
POST /api/v1/jobs备份操作员创建作业：文件、磁盘映像（一块磁盘、用 -1 表示全部磁盘，或部分分区）、Linux 系统或复制，例如 {"name": "PC-07", "kind": "image", "agent_id": 12, "target_id": 3, "image_disk": 0, "image_partitions": [3], "schedule": {"kind": "daily", "days": [1, 2, 3, 4, 5], "times": ["22:00"]}, "retention": {"keep_daily": 14}}；与作业表单相同地检查。备份前后的命令需要管理员角色
PATCH /api/v1/jobs/{id}备份操作员更改名称、路径、排除项、计划、保留或选项；未给出的字段保持不变。启用四眼审批时，缩短保留须在控制台中进行（409）
DELETE /api/v1/jobs/{id}备份操作员删除作业；其备份保留在存储上。启用四眼审批时只能在控制台中删除（409）
POST /api/v1/jobs/{id}/run还原操作员立即启动作业：{"run_id": 123}（202），如已有运行在进行则返回 409
POST /api/v1/jobs/{id}/test还原操作员对作业的最新备份启动还原测试
GET /api/v1/runs?job=&agent=&status=&limit=查看者最近的运行，最新的在前（默认 100，最多 1000）
GET /api/v1/runs/{id}查看者单次运行及其消息、错误和统计信息
GET /api/v1/report?period=&from=&to=&agent=&job=查看者某个时段的报告：合计、成功率和每个作业的详情
GET /api/v1/targets查看者存储目标（不含凭据）
POST /api/v1/targets管理员使用存储表单中的字段创建存储目标，例如 {"name": "Customer A", "kind": "s3", "s3_endpoint": "…", "s3_bucket": "…", "s3_access_key": "…", "s3_secret_key": "…", "s3_lock_days": 30}；除非指定 "encrypted": false，否则加密。会测试连接，并仅返回一次恢复密钥——请妥善保管
POST /api/v1/targets/{id}/test管理员测试与存储的连接：{"ok": true, "message": "…"}
POST /api/v1/agents/enroll-code备份操作员用于注册一个代理的代码，有效期 7 天：{"code": "BZ1-…", "expires": "…"}
GET /api/v1/agents/{id}查看者单个代理，含其报告的磁盘和分区（在映像备份中按编号选择）
POST /api/v1/agents/{id}/log备份操作员请求代理发送其日志：{"run_id": 124}；代理发送后用下一个端点读取（需要代理 0.38.0 或更高版本）
GET /api/v1/runs/{id}/log备份操作员代理发送的日志：{"log": "..."}，到达之前返回 404
POST /api/v1/runs/{id}/cancel还原操作员取消排队中的运行或停止正在进行的运行：{"state": "cancelled"} 或 "stopping"；已结束则返回 409
POST /api/v1/jobs/{id}/enable, /disable备份操作员开启或关闭作业的计划；启用四眼审批时只能在控制台中禁用（409）
GET /api/v1/storage查看者每个存储目标的已用空间，已知时还有容量和可用空间、每日增长和预计用满的天数
GET /api/v1/metrics查看者Prometheus 文本格式的指标（见下文）
POST /api/v1/runs/{id}/restore还原操作员由代理恢复某次备份中的文件：请求体 {"target": "D:/Restore"} 或 {"original": true}，可选 "paths"、"agent_id" 和 "verify": true；返回 {"run_id": 125}
GET /api/v1/runs/{id}/files?path=还原操作员列出网络存储上文件备份或 Linux 系统备份的文件夹（path= 取自上一次列表）：{"entries": [{"name": "…", "path": "…", "dir": false, "size": 16, "modified": "…"}]}
POST /api/v1/runs/{id}/files/download还原操作员下载备份中的文件：请求体 {"paths": ["…"]}；单个文件按原样，多个文件或文件夹为 ZIP 压缩包
GET /api/v1/openapi.json无需令牌本 API 的 OpenAPI 3 规范，供工具和客户端生成器使用（也在仓库中：internal/server/openapi.json）

时段：today、yesterday、last7、last30、last90、thisweek、lastweek、thismonth、lastmonth，或 custom 加 from=2026-09-01&to=2026-09-30。

错误返回 {"error": "..."}，状态码为 400（请求有误）、401（令牌缺失、无效或已过期）、403（角色权限不足）、404 或 409。

示例

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

仅在可信网络中针对控制台的自签名证书使用 -k / -SkipCertificateCheck，或者在监控主机上安装控制台证书。

监控检查

每隔几分钟轮询一次 /api/v1/status，当 ok 为 false 时发出警报。若要按作业检查，请使用 /api/v1/jobs，当 last_status 为 failed 或 last_finished 早于预期时发出警报。

设置了 RPO 的作业还会返回 rpo_hours、rpo_met 和 last_good_backup；代理会返回 max_runs（同时作业数）。指标 backupzit_job_rpo_met 对符合 RPO 的作业为 1，对未达成的作业为 0。

Prometheus 和 Grafana

/api/v1/metrics 以 Prometheus 文本格式返回状态：在线代理、活动运行、最近 24 小时的失败和警告、可疑备份，以及每个代理、作业和存储目标的 backupzit_agent_online、backupzit_job_last_status（0 成功，1 警告，2 失败）、backupzit_job_last_success_timestamp_seconds、backupzit_storage_used_bytes 和 backupzit_storage_free_bytes。使用查看者令牌的抓取作业：

- job_name: backupzit
  scheme: https
  metrics_path: /api/v1/metrics
  authorization:
    credentials: bzt_...
  static_configs:
    - targets: ['backup.example.local:8443']

例如当 time() - backupzit_job_last_success_timestamp_seconds > 2*86400（两天没有成功备份）时告警。
