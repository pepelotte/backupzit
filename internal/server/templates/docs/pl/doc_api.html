REST API

Zintegruj BackupZit z platformami RMM, monitoringiem (PRTG, Zabbix, Nagios, Uptime Kuma …) i własnymi skryptami.

Tokeny

Utwórz token w Moje konto → Tokeny API. Nadaj mu najniższą wystarczającą rolę — Obserwator do monitoringu, Operator przywracania, aby także uruchamiać kopie i testy przywracania. Token jest pokazywany tylko raz; wysyłaj go w każdym żądaniu:

Authorization: Bearer bzt_...

Tokeny mogą wygasać, mogą zostać odwołane przez właściciela lub administratora (Użytkownicy) i przestają działać, gdy właściciel zostanie wyłączony. Działania wykonane tokenem pojawiają się w dzienniku audytu z nazwą tokenu.

Punkty końcowe

Wszystkie odpowiedzi są w JSON. Bazowy URL: https://<konsola>:8443.

Metoda i ścieżkaRolaZwraca
GET /api/v1/statusObserwatorOgólny stan: agenci online, błędy i ostrzeżenia w ciągu 24 h, aktywne uruchomienia, niesprawdzone podejrzane kopie, "ok": true|false
GET /api/v1/agentsObserwatorAgenci z systemem, wersją, stanem online i ostatnim kontaktem
GET /api/v1/jobs, GET /api/v1/jobs/{id}ObserwatorZadania z harmonogramem, następnym uruchomieniem i ostatnim wynikiem; także ich ustawienia: schedule_spec, retention, options, image_disk, image_partitions
POST /api/v1/jobsOperator kopiiTworzy zadanie: pliki, obraz dysku (jeden dysk, wszystkie przez -1 lub wybrane partycje), system Linux lub kopię, np. {"name": "PC-07", "kind": "image", "agent_id": 12, "target_id": 3, "image_disk": 0, "image_partitions": [3], "schedule": {"kind": "daily", "days": [1, 2, 3, 4, 5], "times": ["22:00"]}, "retention": {"keep_daily": 14}}; sprawdzane jak w formularzu. Polecenia przed i po kopii wymagają roli Administrator. Harmonogramy można też ograniczyć do miesięcy ("months": [1, 4, 7, 10]) i okresu ("valid_from", "valid_until"), uruchamiać co miesiąc w wybrany dzień tygodnia ("week": 1, "weekday": 1 = pierwszy poniedziałek), w oknie z minutami ("from_time": "08:30", "to_time": "17:45") lub kilka godzin po poprzednim uruchomieniu ({"kind": "since_last", "every_hours": 36})
PATCH /api/v1/jobs/{id}Operator kopiiZmienia nazwę, ścieżki, wykluczenia, harmonogram, retencję lub opcje; niepodane pola pozostają. Przy zatwierdzaniu na cztery oczy krótszą retencję zmienia się w konsoli (409)
DELETE /api/v1/jobs/{id}Operator kopiiUsuwa zadanie; jego kopie pozostają w magazynie. Przy zatwierdzaniu na cztery oczy tylko w konsoli (409)
POST /api/v1/jobs/{id}/runOperator przywracaniaUruchamia zadanie teraz: {"run_id": 123} (202) lub 409, jeśli uruchomienie jest już aktywne
POST /api/v1/jobs/{id}/testOperator przywracaniaUruchamia test przywracania najnowszej kopii zadania
GET /api/v1/runs?job=&agent=&status=&limit=ObserwatorOstatnie uruchomienia, od najnowszych (domyślnie 100, maks. 1000)
GET /api/v1/runs/{id}ObserwatorJedno uruchomienie z komunikatem, błędami i statystyką
GET /api/v1/report?period=&from=&to=&agent=&job=ObserwatorRaport za okres: sumy, odsetek sukcesów i szczegóły dla każdego zadania
GET /api/v1/targetsObserwatorMagazyny docelowe (bez danych logowania)
POST /api/v1/targetsAdministratorTworzy magazyn z polami formularza Magazyn, np. {"name": "Customer A", "kind": "s3", "s3_endpoint": "…", "s3_bucket": "…", "s3_access_key": "…", "s3_secret_key": "…", "s3_lock_days": 30}; szyfrowany, chyba że "encrypted": false. Testuje połączenie i jednorazowo zwraca klucz odzyskiwania — przechowuj go bezpiecznie. Z "recovery_key_from": 3 używa klucza odzyskiwania celu 3 i żadnego nie zwraca — jeden klucz np. dla NAS i kopii w chmurze
POST /api/v1/targets/{id}/testAdministratorTestuje połączenie z magazynem: {"ok": true, "message": "…"}
POST /api/v1/agents/enroll-codeOperator kopiiKod do rejestracji jednego agenta, ważny 7 dni: {"code": "BZ1-…", "expires": "…"} Opcjonalna treść {"ttl_minutes": 120, "single_use": true, "label": "…"}: krótsza ważność, tylko jeden agent i etykieta, którą agent zachowuje (enroll_label w GET /api/v1/agents)
GET /api/v1/agents/enroll-codes?label_prefix=Operator kopiiWażne kody rejestracji i odzyskiwania, bez samego kodu: [{"id": 7, "label": "…", "single_use": true, "expires": "…"}]
POST /api/v1/agents/enroll-codes/revokeOperator kopiiUnieważnia jeden kod {"id": 7} lub wszystkie, których etykieta zaczyna się od prefiksu {"label_prefix": "…"}; już zarejestrowani agenci pozostają
GET /api/v1/agents/{id}ObserwatorJeden agent z zgłoszonymi dyskami i partycjami (ich numery wybierają je w kopiach obrazu). Partycje mają used: zajęte miejsce przy najnowszej kopii obrazu
POST /api/v1/agents/{id}/logOperator kopiiProsi agenta o dziennik: {"run_id": 124}; odczytaj go kolejnym punktem, gdy agent go wyśle (agenci 0.38.0 lub nowsi)
GET /api/v1/runs/{id}/logOperator kopiiDziennik wysłany przez agenta: {"log": "..."} albo 404, dopóki nie dotrze
POST /api/v1/runs/{id}/cancelOperator przywracaniaAnuluje oczekujące uruchomienie lub zatrzymuje trwające: {"state": "cancelled"} lub "stopping"; 409, jeśli już się zakończyło
POST /api/v1/jobs/{id}/enable, /disableOperator kopiiWłącza lub wyłącza harmonogram zadania; przy zasadzie czterech oczu wyłączenie jest możliwe tylko w konsoli (409)
GET /api/v1/storageObserwatorZajęte miejsce na magazyn, pojemność i wolne miejsce, jeśli są znane, przyrost dzienny i dni do zapełnienia
GET /api/v1/metricsObserwatorMetryki w formacie tekstowym Prometheus (patrz niżej)
POST /api/v1/runs/{id}/restoreOperator przywracaniaPrzywraca pliki z kopii za pomocą agenta: treść {"target": "D:/Restore"} lub {"original": true}, opcjonalnie "paths", "agent_id" i "verify": true; zwraca {"run_id": 125}. Dla obrazu dysku podaj ścieżki tak, jak pokazuje je lista plików; "run_ids" wymienia jedno uruchomienie na wolumin
POST /api/v1/runs/{id}/restore-diskOperator przywracaniaPrzywraca obraz dysku na cały dysk agenta, także uruchomionego z nośnika odzyskiwania: {"disk": 0, "target_disk": 1, "confirm_erase": true}, opcjonalnie "agent_id", "new_hardware", "keep_offline", "driver_path"; kopię systemu Linux z {"device": "/dev/sdb", "confirm_erase": true}. Dyski kopii są w image_disks z GET /api/v1/runs/{id}
GET /api/v1/runs/{id}/files?path=Operator przywracaniaWyświetla folder kopii plików lub systemu Linux w magazynie sieciowym (path= z poprzedniej listy): {"entries": [{"name": "…", "path": "…", "dir": false, "size": 16, "modified": "…"}]}. Dla obrazu dysku pierwszy poziom pokazuje jego woluminy (C dla C:\); pobieranie i przywracanie używają tych samych ścieżek
POST /api/v1/runs/{id}/files/downloadOperator przywracaniaPobiera pliki z kopii: treść {"paths": ["…"]}; jeden plik bez zmian, kilka lub foldery jako archiwum ZIP
GET /api/v1/openapi.jsonbez tokenuSpecyfikacja OpenAPI 3 tego API dla narzędzi i generatorów klientów (także w repozytorium: internal/server/openapi.json)

Okresy: today, yesterday, last7, last30, last90, thisweek, lastweek, thismonth, lastmonth lub custom z from=2026-09-01&to=2026-09-30.

Błędy zwracają {"error": "..."} z kodem 400 (błędne żądanie), 401 (brak tokenu, token nieprawidłowy lub wygasły), 403 (zbyt niska rola), 404 lub 409.

Przykłady

curl

curl -sk -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/status
curl -sk -X POST -H "Authorization: Bearer $BZ_TOKEN" https://backup.example.local:8443/api/v1/jobs/7/run

PowerShell

$h = @{ Authorization = "Bearer $env:BZ_TOKEN" }
$s = Invoke-RestMethod -Uri https://backup.example.local:8443/api/v1/status -Headers $h -SkipCertificateCheck
if (-not $s.ok) { Write-Warning "BackupZit needs attention: $($s.failed_24h) failed backups" }

Używaj -k / -SkipCertificateCheck tylko z certyfikatem samopodpisanym konsoli w zaufanej sieci albo zainstaluj certyfikat konsoli na hoście monitoringu.

Sprawdzanie w monitoringu

Odpytuj /api/v1/status co kilka minut i alarmuj, gdy ok ma wartość false. Do sprawdzania poszczególnych zadań użyj /api/v1/jobs i alarmuj, gdy last_status to failed albo last_finished jest starszy niż oczekiwano.

Zadania z RPO zwracają też rpo_hours, rpo_met i last_good_backup; agenci zwracają max_runs (zadania naraz). Metryka backupzit_job_rpo_met wynosi 1 dla zadania w ramach RPO i 0 dla zadania, które go przekroczyło.

Prometheus i Grafana

/api/v1/metrics zwraca stan w formacie tekstowym Prometheus: agenci online, aktywne uruchomienia, błędy i ostrzeżenia z ostatnich 24 godzin, podejrzane kopie oraz dla każdego agenta, zadania i magazynu backupzit_agent_online, backupzit_job_last_status (0 sukces, 1 ostrzeżenie, 2 błąd), backupzit_job_last_success_timestamp_seconds, backupzit_storage_used_bytes i backupzit_storage_free_bytes. Zadanie scrape z tokenem Obserwatora:

- job_name: backupzit
  scheme: https
  metrics_path: /api/v1/metrics
  authorization:
    credentials: bzt_...
  static_configs:
    - targets: ['backup.example.local:8443']

Alarmuj na przykład, gdy time() - backupzit_job_last_success_timestamp_seconds > 2*86400 (brak dobrej kopii od dwóch dni).
